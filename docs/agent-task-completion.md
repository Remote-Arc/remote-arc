# Task completion before optimization

The previous runtime could end a normal task after inspecting account metadata. Three mechanisms caused premature final answers: reading an inbox prohibited every subsequent tool, two cached observations anywhere in the run forced final-only inference, and the bootstrap Free window allowed only eight decisions and 24,000 total tokens. The system prompt also included employee and scheduling manuals on every ordinary owner turn. Passing scripted decisions through these paths did not establish that the actual model could choose useful actions.

Owner tasks now receive direct execution instructions; employee and scheduled contexts retain their specific instructions. Connected mail and calendar accounts expose ready-to-use content reads, server time and bounded calendar dates. Account metadata is sufficient to start reading. These capabilities come from the owned connection registry, not from a phrase-matching router.

Inbox review permits further read-only App operations, including calendar events. The server checks operation permissions and account ownership even for restored decisions. Mail cannot authorize writes, computer execution or delegation. Explicit write workflows use ordinary App message reads instead of the read-only inbox helper. Known failed App reads return an observation so the agent can inspect other sources and explain the gap. Uncertain writes retain the existing stop-and-inspect behavior.

Cached observations are reused without converting the whole run to final-only mode. Optional hints are discarded before durable execution handles under context pressure. Calendar compaction preserves titles, times, time zones and links. Exact verification scopes expose only the selected connection while retaining the frozen scope and required read-back.

Untouched bootstrap execution windows become Free 32 decisions/128k tokens/15 minutes, Plus 48/192k/30 minutes, and Pro 64/256k/60 minutes. Explicit published administrator settings and modified bootstrap policies remain authoritative. Prices, credits, quotas, funding limits and cancellation are unchanged. These are ceilings, not an instruction to consume every available call.

The evaluation matrix contains 21 scenarios: differently worded Chinese/English attention requests, empty mail, unavailable mail with usable calendar data, calendar preparation, Chinese/English GitHub issue creation, Chinese/English deployment checks, failed deployments, scheduled work, selected Skills, managed process completion, three exact verification contracts, two different project abbreviations and a project follow-up after 110 intervening messages. Source facts and final outcomes are checked; identifying connected accounts is insufficient. Model repair, scope errors, read-back, cancellation, account boundaries and uncertain writes also have runtime regressions.

`pnpm --filter @remotearc/relay test:arc` uses scripted inference and synthetic providers to verify execution contracts and fixture validity. It is not real-model acceptance. `scripts/arc-task-live-eval.ts` uses actual Auto inference against synthetic accounts/providers through the normal gateway and ledger, with a USD 0.05 evaluation ceiling and no real customer writes. Its protected workflow requires authorization to use its model credential. Success is evidence for evaluated task families, not a guarantee for arbitrary tasks. Keep paraphrases, source failures and follow-ups in the matrix as the agent changes.

## Project and conversation continuity

Ordinary owner inference now carries up to 32 recent messages, authenticated original user goals, relevant project observations with source message IDs/times, recent answers, and a live owned teammate index. A bounded journal read reconstructs this working context rather than trusting a generated summary as a new instruction. The transport guard increases from 64 KB to 256 KB; this is an application byte limit, not a claim about a model's token window. Funding reservations remain independent. Compaction discards optional catalogs and duplicated prose before execution handles and acknowledged-action records; it never drops old completed actions merely to make room for a new tool call.

`read_context` searches older encrypted chat messages and scans project catalogs through the normal App ownership/scope/quota gateway. GitHub, Vercel, Notion and Drive metadata are supported; matching GitHub repositories are followed to actual observed README paths and content. Candidate initials derive from observed names, with no production special case for RA, CM or a particular project. A candidate is not a confirmed definition. Other sources remain available through normal `call_app` searches. Coverage reports unavailable sources, catalog excerpts, unscanned connections and older chat cursors; `before` plus `includeApps:false` continues journal retrieval without rescanning Apps. Reads observe cancellation/deadlines. Retrieved text is untrusted data, never write authority. Children cannot call the owner's discovery helper.

The former 200-message admission cap is removed. Recent display remains bounded, while an owner-bound cursor endpoint loads all earlier messages without skipping tied timestamps. The client preserves loaded history across new snapshots, retains current run states, keeps the reading position when prepending messages and follows new work when the user returns to the bottom.

## Teammate continuity and progress

Delegation freezes the relevant original user goals and project source excerpts alongside the current message and assignment. Nested delegation inherits this packet; it does not query the owner's private memory or grant new App/device permissions. Existing live scope intersection, revocation, depth and cancellation checks remain authoritative.

The mention picker refreshes whenever opened and when created employee/connection cards change while it is open. Account changes still clear selections and in-flight requests. Chat snapshots expose actual owner-scoped dispatch/delivery/run states and the latest public tool label. A visible progress card shows each member as queued, working, completed, failed, stopped or uncertain while the existing poller continues after the parent replies. No separate model is used to manufacture progress.

Auto configuration no longer rejects every OpenAI model except Luna. A server-selected priced allowlist entry such as `ARC_AUTO_MODEL_ID=gpt-6.1-sol` can be used as Auto; arbitrary browser-selected models still require their normal access. This patch does not change the deployed Auto default, model prices or funding policy. Quality comparison with the deployed model is still required. Official model guidance: https://developers.openai.com/api/docs/guides/latest-model

Local integration coverage includes a 263-message chat, complete cursor traversal, cross-owner/cross-chat cursor denial, sourced project retrieval, generic initials, partial App failure, cancellation, a live roster, delegated background with unchanged child access, queued/working/completed/failed/unknown/cancelled progress, client history retention and fresh mention lists. Browser acceptance covers desktop/mobile and both languages. All local provider/model fixtures must be identified as synthetic; none establish that the live model has met the quality bar.
