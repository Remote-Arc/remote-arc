# Apps in conversation

Users describe an outcome in ordinary language. Connected Apps are available directly to Arc and compatible MCP clients; the Apps directory no longer offers copied execution prompts or internal operation identifiers. Arc resolves resource names and links through search/list/read operations before writing. If the target remains ambiguous, it asks about the resource in human terms. It must report the provider's observed outcome rather than claim success from intent alone.

When an owner chat needs an account or additional provider access, `connect_app` adds a connection card beneath that turn. The task pauses without inference or automatic provider polling. OAuth opens from that card and returns to the original conversation; successful authorization resumes the same run without a second user instruction. Existing eligible connections are reused without another card. API credential providers use the existing secure connection form inside the card; credentials never enter chat history or model arguments.

Migration `0054_arc_app_connections.sql` adds owner-bound connection requests. OAuth state contains an encrypted request handle, never a caller-controlled return URL. Resumption checks account ownership, provider, granted scopes, session state, cancellation and expiry. Waiting time does not consume the run's remaining execution time; tokens, completed steps and tool-call identities are retained. A repeated callback does not replay an acknowledged write. New user instructions cancel a previous pending connection task in the same chat. Cancelled or deleted chats cannot resume through an old connection link. Expired requests can be renewed explicitly, without resetting execution budgets. Scheduled jobs, team rooms and teammate runs cannot request owner consent through this flow.

The public chat snapshot exposes `waiting_connection` while the durable run waits. Connection metadata is private and not cached. Unconfigured Apps display an unavailable card with the saved task; they do not offer a broken sign-in button. Provider denial and partial grants return to the same chat with a retry message. Preview mode simulates connection and completion locally and keeps provider credentials and real mutations disabled.

`pnpm --filter @remotearc/relay test:apps` includes a SQLite/runtime integration test covering one natural-language Notion goal, account connection, same-run OAuth resumption, search, read, archive and read-back. Provider HTTP and model decisions are scripted: this verifies the application contract, not live provider acceptance or general model reliability. It also covers repeated callbacks, partial scopes, cancellation, expiry, malformed bodies, CSRF, account boundaries and reuse of existing connections. Browser QA covers EN/ZH, desktop/mobile and light/dark layouts with exactly one user message and no copied commands or ID fields.
