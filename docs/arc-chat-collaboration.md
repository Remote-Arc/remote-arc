# One conversation for coordinated work

Arc Chat is the sole entry for starting and continuing work. A user gives a goal, Arc chooses or creates appropriate teammates, organizes the requested team, delegates the work and returns actual outputs to the originating conversation. A clear creation or execution request does not require a second review card or a separate team messenger.

This release adds owner-chat `create_team` using actual owned teammate IDs, with deterministic retry identity, active-source checks and no resource grants. Explicit previews and negative requests remain previews. Existing delegated execution, live scope checks, concurrency limits and the no-idle-inference model are reused. A team creation never by itself starts inference. A request that also asks for discussion/work continues through `delegate_work`. Actual replies are preserved in the originating chat rather than truncated and linked to another messenger. Internal team rooms stay out of the user's recent-chat and Activity lists.

Teammate identities and saved team membership are optional Settings → Teammates data. The independent Teams chat page and its manual conversation creation are removed. Legacy team URLs redirect to settings, where previous messages can be read without another composer. User-facing work details and change history contain readable actions/statuses rather than raw request or response payloads. All app-owned scrollbars are visually hidden while native wheel, touch and keyboard scrolling are retained, including Admin.

Chat uses structured @ references for teammates, apps and reusable workflows, visible with identity icons in both the composer and saved messages. Selecting a teammate preserves its owned ID and routes within the same owner chat, rather than creating a second chat UI. Reference labels and skill text are data, never authority to grant permissions.

Elastic execution should be goal-scoped: temporary specialists exist only as required, respect the task's current authorized resources and budget, and report progress/results to the same conversation. Persistent identity settings are optional. This release does not yet implement temporary role retirement, task-scoped resource inheritance, or automatic reallocation of work after every new user instruction; it does not claim those capabilities based only on the redesigned UI.

Skills should describe an achievable outcome, required inputs/resources, concrete execution and checks, recovery, and a useful deliverable. An imported instruction file is guidance; it is not an installed executor. The current account library has five Arc workflows (inbox excerpts, GitHub issue, deployment readiness, website and report), while the device catalog is a separate guidance pack. Production and PR previews now share the five Arc workflows. Cards show outcomes and required resources, then open Chat with a prompt and structured workflow reference. Connected-resource indicators are observations of connection status, not certification that all permissions or dependencies are ready. Normal chat requests reuse task authorization; formal verification requests retain their exact enforced scope and receipts. Do not delete imported user content or imply engines are installed without checking.

PR previews are explicit local simulations. The four-role example demonstrates the intended single-conversation shape without making model calls or accessing real tools. Production team tests use real SQLite, scripted model decisions and actual dispatch/report code. They establish the implementation contracts, not the quality of live model decisions.
