# One conversation for coordinated work

Arc Chat is the sole entry for starting and continuing work. Natural-language goals are sufficient; @ references and the workflow library are optional ways to specify context, never prerequisites or onboarding steps. A user gives a goal, Arc chooses or creates appropriate teammates, organizes the requested team, delegates the work and returns actual outputs to the originating conversation. A clear creation or execution request does not require a second review card or a separate team messenger.

This release adds owner-chat `create_team` using actual owned teammate IDs, with deterministic retry identity, active-source checks and no resource grants. Explicit previews and negative requests remain previews. Existing delegated execution, live scope checks, concurrency limits and the no-idle-inference model are reused. A team creation never by itself starts inference. A request that also asks for discussion/work continues through `delegate_work`. Actual replies are preserved in the originating chat rather than truncated and linked to another messenger. Internal team rooms stay out of the user's recent-chat and Activity lists.

Teammate identities and saved team membership are optional Settings → Teammates data. The independent Teams chat page and its manual conversation creation are removed. Legacy team URLs redirect to settings, where previous messages can be read without another composer. User-facing work details and change history contain readable actions/statuses rather than raw request or response payloads. All app-owned scrollbars are visually hidden while native wheel, touch and keyboard scrolling are retained, including Admin.

Chat's + menu offers photos, files, places, apps, teammates, skills and browser dictation. Structured references remain optional and show identity icons in both the composer and saved messages. Selecting a teammate preserves its owned ID and routes within the same owner chat. Reference labels, attachment contents and skill text are data, never authority to grant permissions.

Uploads are real authenticated owner-scoped resources, not pasted excerpts. The UI supports file selection, drag/drop and clipboard images; it resizes images to at most 2048 pixels per edge and 2 MB. Up to three files accompany a message. PNG/JPEG images go through the model's actual image input channel; PDF (up to 60 pages), DOCX and UTF-8 text/code are extracted with an explicit truncation flag and a shared 16 KB text context limit. Scanned PDFs require page images. Images reserve input cost before dispatch; existing monetary caps still apply. Attachments and their metadata are encrypted in bounded D1 chunks, with 32 MB per owner, 30 uploads per hour, 24-hour unattached expiry and 30-day message attachment expiry. Deleting a chat deletes its attachments. Retention purges expired chunks. Retries use a stable upload key, and a file is bound only when a message is accepted; another chat/account cannot attach it. Owner-request attachments/location follow an authorized teammate dispatch without granting app or device access.

A place can be typed without browser permission. Current location is requested only after an explicit click. Dictation uses the browser's SpeechRecognition implementation and never sends the message automatically; unsupported browsers expose a disabled control. Browser/service support and microphone/location permissions can vary. This release does not claim a universal cloud transcription service or voice conversation mode.

Elastic execution should be goal-scoped: temporary specialists exist only as required, respect the task's current authorized resources and budget, and report progress/results to the same conversation. Persistent identity settings are optional. This release does not yet implement temporary role retirement, task-scoped resource inheritance, or automatic reallocation of work after every new user instruction; it does not claim those capabilities based only on the redesigned UI.

The primary Skills library contains sixteen packages: twelve real upstream packages plus four original Remote Arc office packages for DOCX, XLSX, PPTX and PDF. The upstream set includes Anthropic frontend-design, webapp-testing and mcp-builder; Microsoft playwright-cli; Vercel react-best-practices and web-design-guidelines; K-Dense Polars, Matplotlib, statistical-analysis, scikit-learn, Seaborn and NetworkX. See [source attribution, licenses and exact revisions](../packages/skills/COMMUNITY-NOTICE.md). Upstream MIT/Apache-2.0 resources retain their actual instructions, helpers and licenses. Original office resources have explicit versions, content hashes and read-only inspectors tested against real artifacts. Categories and keyword search cover both sources. Source-available third-party office packages are not redistributed. Earlier Arc verification guides remain readable by ID, and imported user content is preserved.

Discovery returns compact metadata; `read_skill` returns the selected entry and a manifest, `read_skill_resource` pages exact pinned resources, and `prepare_skill` writes selected helpers into the authorized computer's task workspace through the existing device tool. Preparation checks the active source before every write, returns real write outcomes, and does not execute arbitrary upstream commands itself. The agent must check/install necessary task-local dependencies, run the task and verify deliverables. A package being available is not a claim that its executor or dependencies are installed. Cards show source, license and runtime needs and optionally open Chat with the real skill ID. Natural-language requests can discover these packages without selecting a card. Existing task authorization, scope enforcement and billing limits remain in force.

PR previews are explicit local simulations. The four-role example is labeled as preview data. Selected files use actual tab-local Blobs and can be previewed/downloaded within that tab; simulated replies do not run tools, charge models, or persist files across a reload. Production uses the authenticated encrypted attachment API, not this preview store. Production tests use real SQLite, real PDF/DOCX parsing and staged source bytes, with scripted provider decisions. They establish implementation contracts, not live model quality, browser speech accuracy or a live connected computer's dependencies.
