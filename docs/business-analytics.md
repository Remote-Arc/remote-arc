# 经营分析：增长、转化与留存

管理员在「经营分析」查看真实账号、业务流程结果和注册批次。生产页面只读取 `/api/admin/analytics` 的 D1 聚合结果，不填充示例经营数字，不展示排查日志或客服跟进队列。设计预览保留空状态；合成数据仅用于自动化测试。

## 统计口径

- 今天、近 7 天、近 30 天采用 UTC 日期并包含当前未结束的一天。对比值来自前一个同长度周期的相同时间进度。早期活跃数据可能不完整。
- 新增用户为实际创建的账号；活跃为有登录、前台页面访问或实际业务调用记录的去重账号，不包括设备心跳和配对轮询。包含管理员的实际使用，排除固定的评审演示账号。
- 新用户的设备配对（用户授权）、成功使用、付费三个达成率，各自以同一批新增账号为分母；是截至当前的达成情况，不把三个目标假定为必经顺序。
- 登录：每次真正受理的邮箱验证码请求或 Google 授权为一次流程。邮箱发送方接收请求不等于邮件送达收件箱；只有真实登录会话创建成功才完成。错误验证码重试不增加流程数。
- 设备：一个配对码为一次流程，从发起、用户授权到经过身份验证的设备联机；轮询不增加尝试数，授权或领取凭据不直接等于上线。历史配对表保留发起与授权证据；最后在线时间可能只是心跳或失败的连接尝试，不能证明 WebSocket 成功。没有完整上线证据的旧流程单独显示数量，不混入新版完成率分母。
- 购买转化：按同一账号和浏览器访问标识去重，关联该次访问之后创建的正式订单。客户端付款返回不作为收款证明，付款及权益均核验后才完成。没有访问归因的正式订单单独进入订单完成率，避免用不同分母强行计算转化。
- 付款和权益来自正式订单、Stripe 核验入账、Credits 与会员记录。测试模式订单不计入。零元优惠订单可完成，但付费用户与收款金额不含零元和已退款记录；金额按本期核验入账日期计算，不是会计净利润。
- 任务：一个实际创建的 Arc run 为一次发起，仅保存为 `succeeded` 的结果算成功，进行中、失败、取消、未知分别保留。
- 所有流程完成率均为成功完成数 / 去重发起数，仍在进行中的流程保留在分母并单列。零分母显示无样本，不显示 0% 或 100%。缺失中间证据时不公布可疑比例。

## 留存

按最近 60 天的注册日期分组，D1、D7、D30 分别指注册后第 1、7、30 个 UTC 自然日再次使用。只将目标观察日已经完整结束、且处于完整采集覆盖范围内的用户纳入分母。汇总用回访人数 / 到期人数加权计算，不平均每天的百分比。

未到期显示「观察中」；历史未采集显示「尚未采集」。历史存在正向回访证据时可保留人数，但不把没有记录直接解释为流失。迁移会保留现有账号、登录会话、事件、Arc 任务和应用调用的正向使用证据；完整观察从部署后的完整 UTC 日开始，并随批次到期自动填入留存率。

## 采集与访问

`0066_business_analytics.sql` 增加去重流程、流程步骤、每日活跃和覆盖起点，精确关联订单入账及完成时间。邮箱和 Google 登录、设备配对与真实连接、业务成功调用由服务端记录；浏览器仅提交允许的非权威访问事件，重新回到可见页面时补记前台回访。

指标表不存验证码、凭据、表单内容、消息、支付明细载荷或邮箱。用户删除后流程和逐日活跃按外键清理，注册批次分母与 D1/D7/D30 标记解除身份关联后保留，避免幸存者偏差；匿名流程保留至清理期限。流程保留 180 天、每日活跃与注册批次保留 400 天，细粒度产品事件仍保留 30 天。采集失败不替换登录、设备或支付结果。

接口仅允许管理员 host 的 GET，实时核验共享会话与管理员角色，返回 `private, no-store`；只返回聚合数值，不返回用户明细或支付平台密钥。新增索引支持日期、用户和访问关联查询。页面刷新为只读查询，不发起扣款或权益补发。

验证覆盖真实 SQLite 全量迁移、实际登录与设备处理链路、重复去重、付款伪成功、历史时间边界、成熟留存与缺失采集；浏览器覆盖中英文、桌面/手机、筛选、图表、场景与空数据状态。

设备页的浏览器实时画面入口位于「管理 → 活动与详情」，不在设备卡片展示。进入活动标签页并展开入口后才查询会话，离开活动页卸载组件并停止定时查询。
