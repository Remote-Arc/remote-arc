# GitHub-native production release reminders

Production deployment is intentionally **manual and reviewer-protected**. Merging to `master` is **not** a production deploy.

## How notifications work

- `.github/workflows/release-ready-notify.yml` runs when the `CI` workflow completes.
- It only acts if the originating run was a **successful push CI** for the current tip of `master` in this repository. It checks GitHub's production deployment history and skips if that exact SHA was already released.
- It creates or updates **one** assigned GitHub issue titled `[Release Ready] Remote Arc production promotion`, mentioning `@yaohuangguan` with the exact SHA and manual release URL. The notification is updated only when the SHA advances; it does not generate a new issue on each CI retry.
- This uses normal GitHub repository notifications, issue mentions and assignments — **no ChatGPT scheduled task slots** and no Resend marketing/OTP email channel.
- **Crucially:** it never dispatches or approves production, never exports/edits D1, never inserts a fake `BACKUP_VERIFIED`, and never reads untrusted build artifacts from another workflow.

Receiving push alerts on iPhone depends on your GitHub Mobile notification settings. The repository issue/mention remains visible even if push alerts are disabled.

## Manually launch from phone

1. In mobile Safari/Chrome, open <https://github.com/Remote-Arc/remote-arc/actions/workflows/deploy-cloudflare.yml>. GitHub Mobile app may not show the workflow dispatch control; use a browser and request desktop site if necessary.
2. Select **Run workflow** and branch `master`. Leave `backup_confirmation` empty for a release without pending production D1 migrations. For pending migrations, the workflow creates, restores, encrypts and verifies a recoverable backup and retains its encrypted artifact before attesting BACKUP_VERIFIED automatically. The backup key must already be provisioned; no plaintext data is uploaded. See phase1-production-release.md.
3. Open the newly created Actions run. Once it requests approval, select **Review deployments** → **production** → **Approve and deploy**.
4. The protected production environment must approve before migration/deploy steps run. Verify the post-deploy health and runtime after the run finishes.

The first reminder for this new workflow is generated by a qualifying future successful `master` CI after this PR merges. Previously merged PR #181 won't retroactively generate a reminder. The review button does not exist until a deployment has been dispatched.
