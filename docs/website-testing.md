# Website regression tests

Run `pnpm test:site` to check the UI's existing unit/behavior suites and the browser matrix. Install Chromium once with `pnpm exec playwright install chromium`. On Windows with Edge already installed, use `$env:PLAYWRIGHT_CHANNEL='msedge'; pnpm test:site`. `pnpm test:site:browser` runs only browser tests.

The matrix derives public routes from the shared bilingual route/document catalog and workspace routes from the dashboard registry. It checks both desktop English/light and mobile Chinese/dark, including all six Admin sections. Assertions cover actual rendered headings and main landmarks, language/theme, viewport overflow, internal route destinations and uncaught browser errors. Unknown routes must show a useful not-found page; trailing slashes preserve public, documentation and workspace routes.

Interaction tests cover app-only setup, app account modal keyboard/focus behavior, transient App loading failure and recovery, draft preservation during an Admin language change, chat completion and draft continuity across browser history, attachment upload/removal, documentation search/navigation, public form consent and preview isolation, checkout selection and simulated payment/refresh, and HTTP/network sign-out failure with keyboard-accessible recovery.

Arc recovery cases delay actual simulated HTTP responses to verify that navigating to a new chat preserves new drafts/attachments, and that a successful send consumes only its submitted files/references. They also cover edits back to the same text, delayed geolocation success/failure after a manual place selection, cancelling location lookup, and image loading inside the sandboxed email preview. Hook tests exercise concurrent sends across navigation, retry-key retention, account changes, trial activation and late cancellation/deletion errors.

Tests start the local Vite app with `VITE_UI_PREVIEW=1`. Accounts and execution are synthetic; all browser requests outside the local test origin are blocked. Preview forms cannot send mail or mutate real customer systems. Passing this suite verifies UI behavior and existing simulated API contracts; production authentication, provider OAuth, live model quality, email delivery and real payments still require their separate integration acceptance tests. It does not measure 100% code coverage.

The `website` CI job runs the suite and a production build on every push and pull request. Failures retain screenshots and traces; `work/site-test-report/index.html` contains the report. Use `pnpm exec playwright show-report work/site-test-report` or `pnpm exec playwright show-trace <trace.zip>` to inspect a failure.
